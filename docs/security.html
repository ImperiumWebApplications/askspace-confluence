Security, Privacy & Least-Privilege Architecture

1. 100% Atlassian-Hosted Compute & Storage

  • Runtime: Atlassian Forge Node.js 22.x serverless runtime (no external AWS, GCP, or third-party servers).
  • Storage: Tenant-isolated Atlassian Forge SQL (MySQL/TiDB) hosted inside Atlassian Cloud with automatic Data Residency alignment.
  • External Egress: None. manifest.yml declares zero external fetch domains or remotes.
  • SQL Injection Prevention: 100% parameterized prepared statements via @forge/sql prepare().bindParams().
  • Permission Enforcement: All Confluence API actions (reading spaces, checking admin rights, creating promoted FAQ pages) execute via api.asUser() — strictly honoring the signed-in user's real Confluence permissions.

2. Minimal OAuth Scopes

Scope Purpose
read:space:confluenceResolve space metadata, populate space dropdown filters, and verify Space Administrator status for governance actions (admin-verified solutions and tag merging).
read:page:confluenceSupport macro context rendering on Confluence pages.
write:page:confluencePower the user-initiated 1-click "Publish to Confluence Page" feature to turn a verified Q&A thread into a Confluence documentation page under the user's own permissions.
read:confluence-userRead the signed-in user's display name and site administrator status so questions, answers, and audit logs show accurate attribution.
storage:appStore tenant-isolated Q&A records, tags, votes, notifications, and audit logs inside Atlassian-hosted Forge SQL.

3. Vulnerability Disclosure

To report a security issue, please open a high-priority ticket via our Support Portal. Critical security reports receive an acknowledgement within 24 hours.
